# 豆包Seedance动作v3：解决“不生动、幅度太小”

日期：2026-11-17。用户使用的界面模型名为doubao-sendance2.0flash，反馈为动作幅度小、缺少参考项目的生动感。本轮针对这两个问题重写；角色图沿用v2.1，无需再重画。

当前入口：[八角色136条](../prompts/chibi-v3/README.md)，[DeepSeek三条试样](../prompts/chibi-v3/PILOT-DEEPSEEK.md)。

## 先看本轮真正改了什么

|问题|上版倾向|v3处理|
|---|---|---|
|身体被限制住|多处要求极轻、小幅、肩翼不动|逐动作写清屈膝、抬臂、转肩、前俯、回弹；安静动作保留其安静属性|
|挥手不明显|手腕轻摆两次|双肘带前臂，从肩外侧到耳旁走大弧线，躯干跟随|
|跳跃像踮鞋尖|最高只移画高4%，准备与收势占很多时间|先压低蓄力、再腾空、落地屈膝与短回弹，脚下空隙可见|
|点按只剩手指颤动|点按幅度小，面板抢镜|前臂在胸口下方到腰前往返，肩背随按压回弹|
|首尾过度静止|头尾各保持约1秒、默认两端锁同图|直接从站姿进入动作、自然收势；首轮幅度试样先不额外锁同图尾帧|
|语言多、主体动作被淹没|同时给多版长描述、外观与限制反复出现|每条投喂稿控制在500字以内，目前最长380字符；只选对应入口的一段|
|纯文字难描述同款节奏|只提供抽象“自然、灵动”|准备17段实际官方动作MP4，并写好动作参考模式|

“同图首尾会压住动作”尚无本项目样片实验证明。本轮先去掉尾帧硬锁是为了减少一个可疑约束，便于分开诊断；它不是对所有模型的结论。文本仍要求最后回位。

## 设计依据

核对[PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)固定版本
[fb38ce62](https://github.com/PC2005-cloud/dsh-pet/commit/fb38ce620576f5ed3735a99536d2b1a4a9eb313f)：
[原动作配方](https://github.com/PC2005-cloud/dsh-pet/blob/fb38ce620576f5ed3735a99536d2b1a4a9eb313f/prompts/桌面宠物%2010%20秒动作提示词.md)
及对应17个实际WebM。17段参考均已真实解码，并抽查挥手、跳跃、点按、庆祝、转圈、悬空的多时刻画面。

火山引擎的[Seedance 2.0提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-0-prompt-guide?lang=zh)
支持将角色外观与动作参考分开定义；其[API文档](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)
建议中文提示词不超过500字，并区分多模态参考与首尾帧模式。本轮据此使用短、具体的动作句和分开的两种入口。
这些是2.0系列依据；用户界面的Flash名称未被擅自映射成某个API型号，也没有虚构“运动强度=某个数”的参数。

## 两种入口，选你界面实际提供的那一种

### A：有全能参考或视频参考入口

1. 图片1选择当前角色的单人绿幕S；拖拽选择H。
2. 视频1选择该动作的[官方参考MP4](../reference/motion-dsh-pet/README.md)。
3. 复制“图片1＋视频1”提示词，选择10秒、16:9。
4. 图片1定义外观、二维画风、构图；视频1只借动作幅度、速度变化和重心。实际素材标签以你在界面插入的标签为准。
5. 在多模态参考模式里，图片是角色参考。不要再同时把它写成API的first_frame/last_frame并混入reference_video；这些是互斥模式。

只有转圈或明显侧背动作需要时再补三视图，并明确为外观辅助。参考素材的“图片1”“视频1”是本文的位置标记，不是你必须重命名的文件名。

### B：只有图生视频入口

1. 上传该角色单人S；拖拽上传H。
2. 复制“仅图片1”提示词，选择10秒、16:9。
3. 第一轮先不额外设置尾帧，观察动作幅度；提示词会要求最后回到参考姿势。
4. 主体动作合格后，若尾帧不准，再单独比较加尾帧控制、补回位片段或挑选更合适的候选片。

默认不把所有角色、三视图和参考视频一次全部塞入，避免主体混淆。

## 三条试样怎样看

先用DeepSeek，尽量保持角色图、时长、比例与模型入口一致。推荐按挥手→跳跃→点按顺序。

|动作|最需要看见的部分|仍然失败时改哪一句|
|---|---|---|
|元气挥手|手从肩外侧摆到耳旁，肩肘带动，上身跟着倾转|改成“双臂从肩下到头两侧完整展开，挥手轨迹至少半个头宽”|
|开心跃动|身体先压低，脚明显离地，落回时膝盖缓冲|强调“先屈膝压低，再蹬直腾空，脚下出现清楚空隙，落地屈膝回弹”|
|忙碌点按|前臂从胸口下方按到腰前，肩背按节奏回弹|强调“每次先抬前臂再完整按下，双肘屈伸，肩背一起发力”|

动得大但脸坏了：保留主动作，先减少临时图形或简化手势；不要重新要求全身都只微动。
手部不好时，归档先用两张纸、取消复杂卷纸。图标不好时，先稳定主体，再在后期加图形。
只有文字更强是否真的有效，必须看新样片，不能用脚本检查代替。

把结果写在[试样记录表](../prompts/chibi-v3/PILOT-RESULTS.csv)。表中目前是空结果，不是已通过记录。
确认幅度、形体与首尾三项后再展开其余角色。八角色136条已经写好，这个顺序是为了尽早发现问题。

## 幅度如何安排

- 待机仍是呼吸、目光与歪头，不硬改成蹦跳。
- 挥手、起跳、庆祝和伸展安排明显的全身动作。
- 思考、出错和归档用姿态变化、重心与表情反差，保持原动作的情绪。
- 只固定镜头、角色比例与构图安全边距；身体各关节可按该动作运动。
- 长发、裙摆、尾翼稍晚跟随，形成收势回弹；跳跃与转圈不一律混在一起。

原地漂浮文件名继续兼容配置，但内容对应上游原地踏步。
张望按当前角色库做S→S回正；上游该片还有偏左→偏右参考图产出用途。
拖拽做H→H持续悬空，参考片只截官方3–7秒中段；上游完整片的起落不复制到循环。
其余大部分沿用上游动作语义。为回应幅度反馈，提高了部分肩身和关节参与度；这是本库适配，不能宣称逐帧复刻上游。

~~~

历史稿在prompts/chibi保留并带新入口提示。不要把历史全文和v3片段叠在一起投喂。

上游视频的干净透明边缘还经过手工抠像，v3重点解决主体表演和幅度。[后续抠像与打包](MAKE-CHIBI-PET.md)继续使用现有流程。
自动化仅验证了参考素材来源、真实解码、任务映射、字数与文件引用。**本轮尚未调用豆包生成新动作视频，生动度与成功率等待实际试样。**
